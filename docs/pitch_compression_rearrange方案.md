# 钢琴 MIDI 音域压缩与重排方案

## 一、目标

在现有音频转 YAML 流水线中新增“音域压缩与重排”阶段，用于解决游戏钢琴音高范围有限的问题。

目标不是简单删除超范围音符，也不是机械八度折叠，而是将完整钢琴 MIDI 的音高、和声与节奏重排到当前游戏可执行键位内，使最终 YAML 在有限音区中尽量保持原曲听感。

## 二、现有问题

当前转换器默认可执行音域为 C3 到 B5，对应 YAML 的低音区、中音区、高音区共 21 个自然音基础键，半音通过组合键表达。

Animenz 这类钢琴编曲通常包含：

1. 高音旋律超过 B5。
2. 低音伴奏低于 C3。
3. 同一拍点出现 8 到 10 个以上音符。
4. 伴奏琶音、内声部与旋律声部叠加。
5. 原曲和声跨度大，直接八度折叠会导致浑浊或声部交叉。

因此，需要从“逐音符映射”升级为“按时间片重排”。

## 三、核心策略

### 3.1 时间片分组

先按 `quantize_beat` 将 MIDI note on 分组为时间片。每个时间片内可能包含旋律音、低音根音、和弦内声部与装饰音。

处理单位从单个音符变为一个时间片：

1. 读取当前时间片全部音符。
2. 识别最高旋律音。
3. 识别最低低音根音。
4. 识别中间和声音。
5. 对整个音集合进行压缩、裁剪与重排。

### 3.2 旋律优先

听感最重要的是旋律线，因此每个时间片优先保留最高有效音符作为旋律候选。

规则：

1. 旋律音允许按八度移动进 C3 到 B5。
2. 尽量放在中高音区，优先 C4 到 B5。
3. 连续旋律之间优先保持相对上行、下行走势。
4. 如果旋律折叠后与伴奏冲突，优先保留旋律。

### 3.3 低音功能压缩

低音通常提供和声根音，不要求保留原始八度。

规则：

1. 低音按 pitch class 映射到低音区或中音区。
2. 优先放到 C3 到 B3。
3. 如果与旋律或和声音冲突，可提升到中音区。
4. 不做伪造低音；只从真实 MIDI 音符中选择。

### 3.4 和声音重排

和声音用于保留和弦色彩，但不能让和弦过密。

规则：

1. 每个时间片最多保留配置数量的音符，例如 4 到 6 个。
2. 必保留旋律音。
3. 尽量保留根音、三音、七音或显著半音色彩。
4. 删除重复 pitch class 的音符，避免八度重复占用键位。
5. 和弦内部音符按低到高排序，输出为 `[低音 中音 高音]`。

### 3.5 音阶压缩方式

建议新增 `--pitch-compression-mode` 参数：

1. `none`：不压缩，沿用当前严格映射。
2. `octave_fold`：只做八度折叠，当前已有策略。
3. `range_rearrange`：按时间片执行旋律优先、低音功能压缩、和声音重排。
4. `global_linear`：先统计全曲 MIDI 音高范围，再用同一个线性比例把所有音符整体压缩到游戏 C3 到 B5 的 36 个半音范围内。

`range_rearrange` 是本次建议实现的核心模式。

### 3.6 全局线性压缩修正

实际听感验证后，单纯 `range_rearrange` 仍可能出现局部违和：原本处于可执行范围内的音符保持不动，而超出范围的音符被单独八度迁移，导致旋律跨越音域边界时像突然换调。

因此需要新增 `global_linear` 模式作为更适合完整钢琴曲压缩的默认方案：

1. 读取 MIDI 后统计全曲最低音与最高音。
2. 将全曲音高范围 `[原始最低音, 原始最高音]` 线性映射到 `[C3, B5]`。
3. 所有音符都经过同一条映射函数，不区分是否原本已经在 C3 到 B5 内。
4. 映射结果四舍五入到最近半音。
5. 同一时间片内映射到同一目标键的音符去重。
6. 同一时间片音符过多时再按旋律、低音、和声优先级裁剪。

该模式的重点是保持全曲整体轮廓一致，而不是保留单个音符的原始八度。

## 四、推荐映射窗口

在 `range_rearrange` 模式下，建议把音符分配到三个目标区域：

1. 低音功能区：C3 到 B3，对应 `-1` 到 `-7`。
2. 和声填充区：C4 到 B4，对应 `1` 到 `7`。
3. 旋律突出区：C5 到 B5，对应 `+1` 到 `+7`。

映射原则：

1. 原始最高音优先映射到旋律突出区。
2. 原始最低音优先映射到低音功能区。
3. 中间音按 pitch class 填充到和声填充区。
4. 若同一 pitch class 已出现，只保留更符合角色的一枚音。

## 五、多键同按规则

为了保持听感，可以适当使用多键同按，但必须限制密度。

建议默认：

1. `max_chord_notes` 从 10 收回到 5 或 6。
2. 每个时间片最多一个低音、一个旋律、三到四个和声音。
3. 若同一时间片音符过多，按优先级裁剪。
4. 裁剪必须记录在报告中，不静默丢弃。

优先级建议：

1. 旋律音。
2. 低音根音。
3. 与旋律构成三度、六度或七度色彩的和声音。
4. 其他中间填充音。
5. 重复八度音。

## 六、报告与可追踪性

转换报告需要新增统计：

1. 原始 MIDI 音符数量。
2. 重排后 YAML 音符数量。
3. 被八度迁移的音符数量。
4. 被去重的 pitch class 数量。
5. 被裁剪的和声音数量。
6. 最大原始和弦音数。
7. 最大输出和弦音数。

这样可以判断压缩强度是否过大。

## 七、执行顺序

1. 在 `MidiToYamlConverter` 中新增时间片重排逻辑。
2. 新增命令行参数 `--pitch-compression-mode`。
3. 新增命令行参数 `--melody-target-octave`，默认 `5`。
4. 新增命令行参数 `--harmony-target-octave`，默认 `4`。
5. 新增命令行参数 `--bass-target-octave`，默认 `3`。
6. 更新转换报告字段。
7. 用现有 MIDI 重新生成 `config/animenz_a_cruel_angels_thesis.yaml`。
8. 回读校验生成 YAML。

## 八、预期效果

相比当前 `octave_fold`：

1. 旋律会更突出。
2. 低音不会随机折叠到高音区造成混乱。
3. 和弦密度会更稳定。
4. 同一拍点多键同按更接近“缩编钢琴谱”，而不是“原谱硬塞进三八度”。
5. 游戏内听感会更清晰，但会牺牲部分原始大跨度与复杂内声部。

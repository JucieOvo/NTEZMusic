# 方案：基于音符角色解耦的双层注意力折叠 (RD-DLAF)

> **作者**：JucieOvo
> **日期**：2026-04-27
> **状态**：待审批

---

## 一、方案名称与核心摘要

**方案名称**：基于音符角色解耦的双层注意力折叠（Role-Decoupled Dual-Layer Attention Folding, RD-DLAF）

**核心创新**：将当前算法中"所有音符共享单一 ref_pitch"的强制耦合打破，为旋律线、低音线、和声填充三条虚拟音轨各自建立独立的因果注意力状态。双层注意力的分工为——

- **全局层**（角色分配注意力）：分析全曲 MIDI，基于音符的旋律运动模式（而非音高绝对值）将每个音符映射到旋律/低音/和声三个角色
- **局部层**（独立轨注意力）：每条音轨维护自己的因果 ref_pitch，独立执行自适应八度折叠，旋律完整保留、低音轮廓保留、和声激进简化

**一句话区别于方案 D**：方案 D 在"时间维度"上做分段解耦（休止符分段 + 双峰检测分左右手），本方案在"角色维度"上做音轨解耦（旋律/低音/和声三条独立注意力轨迹）。

## 二、方案 D 与本方案的核心差异对照

## 三、算法完整流程（四阶段）

### 阶段一：音符事件预处理与量化

**输入**：88 键钢琴 MIDI 文件（与现有流程一致）
**输出**：量化时间片映射 `grouped_pitches: dict[int, list[int]]`，键为量化网格索引，值为该时间片内所有原始 MIDI 音高列表

**步骤**：
1. 从 `pretty_midi` 读取所有非鼓音符，过滤 `end <= start` 的无效事件
2. 使用 `quantize_beat`（默认 0.25 拍）将 `start_beat` 量化为网格索引
3. 按时间片聚合同一拍点内的所有 MIDI 音高

**与现有代码关系**：完全复用 `_read_midi_notes` 和 `_quantize_to_index`，零改动。

---

### 阶段二：全局音符角色分配（Global Role Assignment Layer）

**职责**：不依赖音高绝对值，而是基于音符的运动模式（旋律性/低音性/和声性）为全曲每个音符分配角色标签。

**输入**：`grouped_pitches`（按时间片排列的音高列表）
**输出**：`role_map: dict[int, dict[int, str]]`，即 `{时间片索引: {原始音高: "melody"/"bass"/"harmony"}}`

**算法步骤**：

#### 2.1 逐时间片初始骨架提取

对每个时间片 `t`，记该时间片的音高集合为 `P_t = sorted(pitches)`。

- **候选旋律音**：`P_t` 中音高最高的那个音符（与现有 `_build_role_priority_candidates` 逻辑一致）
- **候选低音音**：`P_t` 中音高最低的那个音符（同上）
- **候选和声音**：排除旋律和低音后的剩余音符

此步骤得到的只是局部贪心最大/最小，会产生大量误判（例如左手跨越到高音区被误判为旋律，右手下探被误判为低音）。

#### 2.2 旋律性评分（Melodicness Score）—— 核心创新

旋律的本质特征是**级进运动**（stepwise motion）。对时间轴上相邻时间片的候选旋律音符，计算"旋律邻接度"：

```
melodic_affinity(p_{t}, p_{t-1}) = 1.0 - min(|p_t - p_{t-1}| / 12.0, 1.0)
```

- 相邻半音内（小二度/大二度）得分接近 1.0
- 跨度超过一个八度的跳跃得分趋近 0

对每个时间片 `t` 的音符 `p`，定义其"旋律连续性分数"为与前后有音时间片的候选旋律音符的最大邻接度加权和：

```
melody_score[t][p] = α * max affinity with t-1's candidates + (1-α) * max affinity with t+1's candidates
```

此分数在整曲层面上做一次前向-后向平滑（类似 Viterbi 解码思想但不是 HMM），选出整曲的**主旋律线**。

**关键设计决策**：不依赖音高绝对值，只依赖音程邻接度，因此低音区和高音区的旋律片段都能被正确识别。例如《残酷天使》中左手低音区的副旋律不会被误判为低音伴奏。

#### 2.3 低音性评分（Bassness Score）

低音的本质特征是**跳进运动**（leap motion，四度/五度跳跃）加上始终处于相对较低位置。定义：

```
bassness_score[t][p] = w1 * pitch_lowness(p, P_t) + w2 * leap_affinity(p, p_{t-1})
```

其中：
- `pitch_lowness` = 音符在 `P_t` 中的百分位倒数（最低音 = 1.0）
- `leap_affinity` = 与前一拍候选低音音符之间的纯四度/纯五度跳进匹配度（5-7 半音跳进 = 1.0，否则衰减）

#### 2.4 角色分配

对每个时间片 `t`，综合评分后分配：
- 得分最高的旋律候选 → `melody`
- 得分最高的低音候选 → `bass`（若与旋律是同音则取消，该拍无双低音）
- 其余 → `harmony`

**与方案 D 的本质差异**：
- 方案 D 用整段音高直方图统计（双峰检测）做左右手切割——这是**静态统计方法**
- 本方案用音符在时间轴上的运动模式（邻接度、跳进模式）做角色识别——这是**动态序列方法**
- 方案 D 的切割线在每个段内是常数，本方案的角色标签是逐时间片自适应变化的

### 阶段三：独立音轨注意力折叠（Per-Role Local Attention Layer）

**职责**：三条音轨各自维护独立的因果 ref_pitch，在各自的目标音区范围内做自适应八度折叠。

**核心原理**：当前 `adaptive_octave_fold` 算法的根本缺陷在于——高音区的旋律会推高 ref_pitch，导致后续低音区进入时被迫做不自然的上八度迁移。本方案通过角色解耦，三条音轨的 ref_pitch 互不干扰，从根本上消除"前段高音拖滞后段低音"的问题。

#### 3.1 音轨目标音区分配（不硬编码，基于全局统计）

对全曲做完角色分配后，收集每条音轨的原始音高范围：

- 旋律轨：统计所有 `melody` 标签音符的 5%-95% 分位数音高范围
- 低音轨：统计所有 `bass` 标签音符的 5%-95% 分位数音高范围
- 和声轨：统计所有 `harmony` 标签音符的 5%-95% 分位数音高范围

然后分配目标音区：
- **旋律轨目标窗口**：基于其原始中位音高，映射到 C3-B5 窗口的上半部（例如 C4-B5），但要保证窗口宽度足够容纳其跨度的 1.2 倍
- **低音轨目标窗口**：映射到窗口下半部（例如 C3-G4）
- **和声轨目标窗口**：填充旋律和低音之间的剩余空间

**关键设计决策**：三条音轨的目标窗口可以有重叠，在阶段四进行轨间碰撞消解。这与方案 D 的"统一折叠窗口"完全不同。

#### 3.2 独立因果 ref_pitch 轨迹

每条音轨 `r ∈ {melody, bass, harmony}` 维护独立的 `ref_pitch_r[t]`：

```
ref_pitch_r[t] = (1 - γ_r) * ref_pitch_r[t-1] + γ_r * mean(mapped_pitches_r[t])
```

其中 `γ_r` 为轨特定平滑系数：
- 旋律轨：`γ_melody = 0.15`（较慢平滑，保持旋律线的听觉连续性）
- 低音轨：`γ_bass = 0.25`（稍快平滑，允许低音线快速转调）
- 和声轨：`γ_harmony = 0.30`（更快，和声填充不需要强连续性）

初始值按全局统计分配：
- `ref_pitch_melody[0]` = 旋律轨原始中位音高 clamp 到目标窗口中点
- `ref_pitch_bass[0]` = 低音轨目标窗口下三分之一点
- `ref_pitch_harmony[0]` = 和声轨目标窗口中点

#### 3.3 轨内八度折叠

每条音轨内的折叠逻辑与现有 `_adaptive_octave_fold_slice` 基本一致：
1. 尝试寻找统一八度偏移 `k`，使该轨该拍所有音符落入该轨的目标窗口
2. 若存在多个可行 `k`，选择使映射后平均音高最接近该轨当前 `ref_pitch_r` 的 `k`
3. 若无统一 `k`，各自独立映射到窗口内最接近 `ref_pitch_r` 的位置

**与现有代码的复用关系**：`_adaptive_octave_fold_slice` 方法仅需增加 `target_window_low` 和 `target_window_high` 参数即可复用，无需重写。

#### 3.4 和声轨激进简化

和声轨的音符在映射后，进行基于音程张力的裁剪（区别于方案 D 的基于数量的分档裁剪）：

**音程张力定义**（在 36 键输出窗口内计算）：
- 根音（最低音）：张力保留权重 = 1.0
- 七音/导音（与最低音差 10 或 11 半音）：权重 = 0.9
- 三音（与最低音差 3 或 4 半音）：权重 = 0.7
- 五音（与最低音差 7 半音）：权重 = 0.4
- 八度叠置（与任意已保留音差 12 的整数倍）：权重 = 0.1

裁剪流程：
1. 对和声轨该拍已折叠音高集合，按升序排列
2. 计算每个音符的张力权重
3. 保留权重最高的 `h_max` 个音符，`h_max = max_chord_notes - (melody_count + bass_count)`
4. 若该拍旋律和低音已经占满 `max_chord_notes`，和声轨该拍全部丢弃

**与方案 D 的本质差异**：
- 方案 D：基于音符数量的分档简化（≤2全留 / 3-4留根音+五度 / ≥5仅根音）——这是**规则式简化**
- 本方案：基于音程张力的权重排序裁剪——这是**乐理驱动的简化**，优先保留有色彩张力的音程（七音、导音），丢弃冗余八度叠置

---

### 阶段四：轨间碰撞消解与 Token 输出

**职责**：三条音轨独立折叠后可能产生目标键位碰撞（两个不同原始音符映射到同一键盘按键）。此阶段以优先级规则消解碰撞并输出 YAML token。

#### 4.1 碰撞消解优先级

```
旋律 > 低音 > 和声
```

即：若旋律轨和低音轨同时映射到同一键位，保留旋律轨的音符，低音轨的做微调：
- 微调策略：尝试将低音轨该音符向上或向下移动 1 个半音（若仍在目标窗口内且不产生新碰撞），否则丢弃该低音音符
- 和声轨碰撞时直接丢弃和声音符（不尝试微调）

#### 4.2 Token 生成

同上一步的碰撞消解结果，调用现有 `_pitch_to_token` 生成 YAML 简谱 token，按音高升序排列后组合为和弦字符串。

#### 4.3 休止符处理

三种休止符类型：
- **全拍休止**（三条音轨该拍均为空）：插入 `notes: "0"` 休止事件
- **部分轨休止**（某条音轨在该拍无音符）：不影响输出，仅做内部状态标记；该轨的 ref_pitch 在无音符拍不做更新（保持上一拍值）
- **段间长休止**：不做特殊分割（与方案 D 不同），由三条独立 ref_pitch 的因果平滑自然过渡

**关键设计决策**：不做显式的"按休止符分段"，因为三条音轨各自的休止模式不同——旋律可能在某拍休止而低音和和声仍在进行。强制按全拍休止分段反而会破坏音轨内部的状态连续性。

#### 4.4 Score 事件生成

与现有 `_build_score_events` 流程完全一致：
1. 按时间片顺序遍历
2. 在空白时间片插入休止符
3. 去重 + 和弦音数限制校验
4. 输出 `notes` + `beat`

## 四、关键设计决策理由

### 决策 1：选择"角色维度解耦"而非"时间维度分段"

**理由**：当前算法的问题根源不是"分段不够细"，而是"不同功能的音符被迫共享同一注意力状态"。旋律线的起伏和低音线的走向是两条独立的信息流，强行用一根 ref_pitch 去跟踪两条轨迹必然导致互相干扰。按休止符分段（方案 D）只能缓解而不能根治，因为在同一个乐段内部，旋律和伴奏对 ref_pitch 的拉扯依然存在。

### 决策 2：角色识别基于"运动模式"而非"音高统计"

**理由**：钢琴音乐中，左手跨越到高音区弹奏副旋律、右手下探到中音区做填充是极其常见的写法。纯音高统计（方案 D 的双峰检测）在面对这类交叉声部时会失效。而运动模式（级进 vs 跳进）是旋律与伴奏的本质区别，不受绝对音高位置影响。

### 决策 3：和声简化基于"音程张力"而非"音符数量"

**理由**：方案 D 的"5 个音以上和声只保留根音"过于粗暴——很多钢琴编曲的精彩之处就在于七和弦、九和弦的色彩张力。丢掉七音只留根音会严重损失和声色彩。音程张力加权裁剪能在信息压缩和音乐保真度之间取得更好的平衡。

### 决策 4：保持完整因果性

**理由**：方案 D 的非因果平滑（双向指数平滑）需要预知整段/全曲未来信息，这在实时弹奏场景（理论上）不可行，在批处理场景中也增加了全曲扫描开销。本方案完全因果，三条 ref_pitch 仅依赖历史信息，可直接嵌入流式处理管线。

### 决策 5：轨间碰撞处理用微调而非丢弃

**理由**：低音线是音乐结构的骨架，碰撞时直接丢弃低音会导致和声根基丢失。微调 1 个半音在听感上的影响远小于丢失根音。同时微调属于破坏性最小的修正方式（不改变音名，仅做八度微调）。

## 五、方案优势分析

### 5.1 解决当前算法的核心缺陷

- **前段高音拖滞后段低音**：旋律轨的 ref_pitch 独立跟踪旋律线，低音轨的 ref_pitch 独立跟踪低音线，互不干扰。即使全曲开头是高音 solo，进入低音段落时低音轨的 ref_pitch 依然在其目标窗口范围内。

### 5.2 音乐保真度

- **旋律完整保留**：旋律轨不做任何裁剪，仅做八度折叠，保证主旋律线条完整
- **低音轮廓保留**：低音轨不做裁剪（仅做碰撞微调），保留和声进行的根基
- **和声色彩优化保留**：张力权重机制优先保留有色彩的七音、导音、变音，丢弃冗余八度叠置

### 5.3 计算效率

- 单趟 O(N) 复杂度（N 为总音符数），不需要分段扫描、不需要双向平滑
- 角色分配在 O(N) 内完成，旋律性评分仅涉及相邻时间片的局部计算
- 三条独立 ref_pitch 的更新是线性操作

### 5.4 可落地性

- 复用现有 `_adaptive_octave_fold_slice` 核心折叠逻辑（仅需增加窗口参数）
- 复用现有 `_pitch_to_token`、去重、碰撞统计等基础设施
- 新增代码集中在角色分配和轨间调度两个模块
- 改动量预估：新增约 300 行，修改约 100 行，新增 1 个 pitch_compression_mode 枚举值

## 六、方案潜在缺陷与缓解措施

### 缺陷 1：角色分配依赖时间邻接，无音时间片过长时可能漂移

**场景**：旋律线出现长时间休止（超过 2 拍），后续旋律恢复时邻接度与休止前候选可能断裂。

**缓解措施**：在旋律性评分中引入"惯性保持"机制——若当前拍无候选旋律且 `t - t_last_melody < THRESHOLD`（如 4 个量化单位），则保持上一拍的角色分配不变。超过阈值后才重新评估。

### 缺陷 2：三条轨独立折叠可能导致轨间音区重叠异常

**场景**：旋律轨目标窗口下界与低音轨目标窗口上界重叠过大，导致视觉上"左右手分不开"。

**缓解措施**：阶段四的碰撞消解 + 目标窗口分配时设置最小间隔约束——旋律轨窗口下界至少高于低音轨窗口上界 3 半音（小三度）。若原始音区范围无法满足此约束（如全曲音域极窄），则退化为重叠窗口 + 碰撞消解。

### 缺陷 3：音程张力权重在纯自然音和声上可能退化

**场景**：曲目通篇使用 I-IV-V-I 三和弦（如简约派流行钢琴），七音和导音几乎不出现，张力权重全部集中在根音和三音上，裁剪效果趋近于方案 D。

**缓解措施**：检测全曲七音/导音出现频率。若低于阈值（如 < 5% 的和弦包含张力音），自动退化为"保留根音 + 最高音"的最小裁剪策略，不做复杂张力计算。

### 缺陷 4：没有延音踏板支持，长休止期间音符断裂

**说明**：这是平台硬约束（游戏不支持延音踏板），本方案和方案 D 均无法解决。不在算法范围内。

## 七、与方案 D 的逐项对比总结

| 对比项 | 方案 D | 本方案 |
|--------|--------|--------|
| 创新切入点 | 在现有折叠算法外部包裹"分段 + 预简化"预处理层 | 将折叠算法的注意力状态从单一全局分解为三条独立音轨 |
| 左右手区分 | 音高直方图双峰检测，段内静态切割线 | 旋律邻接度 + 低音跳跃模式，逐时间片动态角色分配 |
| 旋律保留策略 | 右手轨完整保留 | 旋律角色完整保留（不限于"右手"，可跨越键盘区域） |
| 简化策略 | 左侧轨道按音数分档（≤2/3-4/≥5） | 和声轨道按音程张力权重排序裁剪 |
| 折叠机制 | 全局双向趋势线 `global_ref[t]` | 三条独立因果 ref_pitch，各轨独立折叠窗口 |
| 分段方式 | 强制按休止符切段，段内统一处理 | 无显式分段，由因果 ref_pitch 自然过渡 |
| 因果性 | 非因果（双向平滑需要未来信息） | 完全因果 |
| 复杂度 | O(N·S)，有分段 + 双向扫描开销 | O(N)，单趟线性扫描 |
| 临界退化 | 全曲无清晰休止符时分段失效；交叉声部时双峰检测失败 | 纯自然音和声时张力权重退化；超长休止时角色分配需要惯性保持 |

| 代码改动量 | 新增分段器 + 简化器 + 趋势线计算，改动量较大 | 新增角色分配 + 轨调度，改动量中等，复用现有折叠核心 |

## 九、附录：方案 D 与本方案的形象类比

- **方案 D** 好比在一条河流（时间轴）上每隔一段距离建一座水坝（休止符分段），每段水库独立调节水位（段内 ref_pitch），水坝的蓄水量由上游趋势（双向平滑）决定

- **本方案** 好比同时管理三条独立的管道——热水管（旋律）、冷水管（低音）、温水管（和声）——每条管道有自己的水压调节阀（独立 ref_pitch），互不串扰，只在出水口（碰撞消解）做最后的混合配比

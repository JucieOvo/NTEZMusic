# 双模态手部错排与主旋律对齐优化方案

## 1. 背景与问题诊断
在多模态对齐之后，用户发现“主旋律跟踪有的时候不对，但一会又对了，可能还是主旋律裁切与选择的问题”。
经过对融合引擎 `src/fusion_engine.py` 进行深入的问题排查，我们定位到了导致主旋律时而丢失、时而恢复的**根本性空间映射 Bug**。

### 1.1 错排 Bug 的运作机制
目前在 `fusion_engine.py` 中，程序对每个发音组（拼合和弦）分配左右手的逻辑是：
1. 抓取该时刻出现的视觉指尖事件，筛选出最近的 $M$ 个指尖（$M \le K$， $K$ 为和弦音符数）。
2. 将这 $M$ 个指尖按物理横坐标（左到右）排序。
3. 对和弦中的 $K$ 个音符按音高（低到高）排序。
4. **拉链式硬性 1-to-1 映射**：
   ```python
   for i, note in enumerate(group):
       if i < m_fingers_count:
           assigned_hand = best_m_fingers[i]["hand"]
       else:
           assigned_hand = self._predict_hand_from_context(...)
   ```

*   **缺陷分析**：
    若视觉检测出现了手指遮挡或遗漏（如 $M < K$），被保留的这 $M$ 个手指（可能只含 1 个左手手指和 1 个右手手指）会被**强行挨个对齐到音符列表中音高最低的前 $M$ 个音符**。
    *   **示例**：右手音轨实际弹奏了高音 `72`，左手弹奏了低音 `48` 和 `52`（共 3 个音）。此时视觉检测到了 2 个手指（1 左, 1 右）。
    *   **旧逻辑映射结果**：
        - 第 0 低音 `48` 对应左侧手指（左手） $\rightarrow$ 正确；
        - 第 1 中音 `52` 对应右侧手指（右手） $\rightarrow$ **错误！`52` 属于左手伴奏，却被标成了右手**；
        - 第 2 高音 `72` 进入 context 补差 $\rightarrow$ 标为右手 $\rightarrow$ 勉强正确。
    *   **致命后果**：
        - 左手伴奏音（`52`）被错误地送进了右手音轨。
        - 后续的主旋律提纯算法（`midi_to_upagain_yaml`）读取右手音轨时，就会在这一瞬间错误地把伴奏低音当成右手旋律，或迫使 Viterbi 平滑器为了迁就这个低音而产生严重的跳动与音级失真（跳切）。当视觉再次把手指认全时（$M = K$），分配恢复正常，听感表现出“一会错一会又对了”的特征。

## 2. 优化方案设计

为了消除拉链式错位，我们应当**把手指原本的“左/右”手标签作为强锚点**。即使部分手指遗漏，也需要将左手对应的音符归为左低音区，右手对应的音符归为右高音区。

### 2.1 锚点分类排序算法
1. 统计当前分组中被检出的左手手指数量 $L$ 和右手手指数量 $R$。由于 `best_m_fingers` 的总数被限制在音符数 $K$ 内，因此一定满足 $L + R \le K$。
2. 构造一个长度为 $K$ 的映射表 `assigned_hands`，默认填充为 `"Unknown"`。
3. **低音左偏绑定**：将音符列表中最低的 $L$ 个音符物理锁定为 `"Left"`。
4. **高音右偏绑定**：将音符列表中最高的 $R$ 个音符物理锁定为 `"Right"`。
5. **中部盲点补差**：若有未被手指覆盖的音符（处于中间的 $K - L - R$ 个音符），使用原本的 `_predict_hand_from_context` 根据历史和音区自适应推测。

### 2.2 示例场景（同上）
*   3 个音符：`48` (Note0), `52` (Note1), `72` (Note2)。
*   检测到 1 个左手手指 ($L=1$)，1 个右手手指 ($R=1$)。
*   **优化后的算法分析**：
    - 最低部的 $L=1$ 个音符（`48`） $\rightarrow$ 直接绑定为 `"Left"`；
    - 最高部的 $R=1$ 个音符（`72`） $\rightarrow$ 直接绑定为 `"Right"`；
    - 中间的 $3 - 1 - 1 = 1$ 个音符（`52`） $\rightarrow$ 触发上下文预测 $\rightarrow$ 基于 C4（音高60）以下和历史，预测出 `"Left"`。
*   **分配结果**：`48` (左), `52` (左), `72` (右)。完美契合物理事实，右手音轨中不会再混入中低音伴奏噪点，从源头上保证了右手提取的主旋律的干净度和还原度。

## 3. 变更实施细节（形式 A）
- **操作类型**：代码修改
- **目标组件**：`src/fusion_engine.py` 中的 `MultiModalFusionEngine.align_and_assign` 方法
- **主要逻辑调整**：
  将 `best_m_fingers` 拆分为 `Left` 和 `Right` 手指列表，计算各自的长度后，依照两端贪婪法将对应的 Left/Right 手标记强行赋予音符组的两端，剩余中部使用 `_predict_hand_from_context` 进行补充。

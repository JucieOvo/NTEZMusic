# UpAgain 时间轴频率采样与极速长音过滤方案

## 1. 目标
通过引入“时间窗口/跳跃频率 (Time Window / Hop Frequency)”量化采样的全新机制，彻底解决原谱中大量极速琶音和碎音在模拟器上发生粘连、导致听觉上“仍然像一堆杂乱和弦”的问题，强制输出最干净的匀速单音序列。

## 2. 意图与当前痛点分析
您提到“现在大量和弦（核显）仍然存在”。但在我们的 V3 版代码中，确实已经强制删除了 `[...]` 并每次只导出了单音。为什么听感上还是像有很多和弦？
根本原因在于：**原转录曲谱（如 EVA）中包含非常密集的极速琶音与花饰音（例如连着四五个 `beat: 0.05` 的起伏短音）**。在非常短的时间内连续弹奏这些独立的单音，因人声残留或模拟器内核执行的微小延迟叠加，导致它们**粘连在了一起，听起来就像是一坨乱七八糟没有去除的和弦！**

这就必须使用您提到的“跳转频率”解决思路：我们需要设定一个固定的时间窗口（如每 `0.25` 拍跳跃一次），将原曲在时间线上“光栅化”。只要是在这个短窗口间挤在一起的所有小音符，全部被熔炼合并成只发一次声的最高音！

## 3. 技术要点 (固定频率时间轴重构)
- **绝对时间轴铺展 (Timeline Unrolling)**：
  先遍历一遍原谱，计算出原谱每一个音的起始拍点 (`start_beat`)。比如第 1 个音在 0 拍开始，第 2 个音在 0.125 拍开始，第 3 个音在 0.250 拍开始。
- **跳转频率采样 (Hop/Quantize Sampling)**：
  设定我们的目标过滤频率步长（比如 `step = 0.25` 拍）。
  从 0 拍开始，每次往后推进 0.25 拍作为一个考察窗口。
  **提取合并**：对于落在当前考察窗口内（例如 0 ~ 0.25拍）的所有音，我们从它们之中仅仅挑选出一个**绝对音高最高**的音符，将其视为该时间窗口的唯一代言音！
- **真·乐理大调化运算叠加**：
  将上述过滤出来、真正干净且匀速分布的主旋律数组，重新送入我们 V3 版的 “全局自动移调找 C大调/A小调” + “重心偏置不越界” 的算法中心。它将输出无论节奏还是旋律都极其清爽的曲谱。

## 4. 模块划分
在 `UpAgainMusicalConverter` 内部新建阶段：
- **Phase 0**: Unroll (铺展时间长串)
- **Phase 1**: Quantize by Hop Frequency (按跳转频率重新切分并提纯)
- 继续走 V3 的最优大调修正和写入逻辑。最终在输出的 YAML 时，所有事件的 `beat` 大多都会是整整齐齐的 `0.25`（或其整数倍组合），再也不会由于零碎极短的 `beat: 0.0625` 引发游戏黏糊发声了。

## 5. 风险点
将花音强行合并锁定到固定网格格律（如全按 0.25 拍或 0.125 拍走），会将原本灵活快速的切分音强制变整齐，可能轻微丢失原曲的动感，但这却是对付模拟器软粘连“和弦”的唯一解法。

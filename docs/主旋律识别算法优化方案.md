# 主旋律识别算法优化方案

## 1. 背景与问题诊断
在目前的 `src/midi_to_upagain_yaml.py` 中，右手音轨（`Right Hand`，其由多模态融合引擎分离出来）的主旋律单音化提取算法采用了“**同拍和弦组内选择最高力度 (Velocity)**”的策略：
```python
voiced_notes = []
for group in onset_groups:
    loudest_note = max(group, key=lambda n: n.velocity)
```
此策略存在两个致命缺陷：
1. **转录力度带来的噪声干扰**：音频转录模型（如 `transkun`）预测出的音符力度（velocity）存在微小的波动和误差。这会导致在一组同时弹奏的右手和弦音符中，伴奏的内声部或装饰音的预测力度可能意外大于主高音旋律线。
2. **钢琴弹奏生理学常识**：在钢琴独奏或右手和弦演奏中，主旋律通常由右手的最外侧手指（如小指、无名指）弹奏，处于该和弦声部的**最高音（Soprano）**位置。即使演奏者进行了轻重对比（voicing），纯粹按力度寻找也极易受转录误差冲击，导致主旋律音高频繁跳跃、破碎。

为了提高主旋律的识别精度，应当将该处提取规则修改为**“同拍右手和弦组内取最高音高（Pitch）”**。这不仅能稳定锁定外声部主旋律，而且符合《UpAgain适配与主旋律缩编方案》中的设计规范（“同拍取最高音”）。

---

## 2. 优化方案概述
### 2.1 变更内容
修改 `src/midi_to_upagain_yaml.py` 中 `MidiMelodyExtractor.extract_melody_events` 内的核心选取算法：
- **原逻辑**：使用 `key=lambda n: n.velocity` 选取力度最大的音符。
- **新逻辑**：使用 `key=lambda n: n.pitch` 选取音高最高的音符作为主旋律。

### 2.2 影响分析与风险控制
- **变更性质**：局部算法参数微调，不涉及外部依赖变更或数据库逻辑。
- **兼容性**：输出的数据格式与后续的 C 大调转换网格化清洗器（`UpAgainTimeHopMusicalConverter`）完全兼容。
- **风险**：几乎无风险，比原力度方案更稳定。极罕见情况下若主旋律在低位声部，音高选取会有偏差，但针对游戏主旋律弹奏而言，最高音始终为最稳妥的白置声部线。

---

## 3. 执行方案与变更细节（形式A）
- **操作类型**：代码修改
- **目标组件**：`src/midi_to_upagain_yaml.py` 中的 `MidiMelodyExtractor` 类
- **修改内容**：将 `extract_melody_events` 方法第136行的 `max(group, key=lambda n: n.velocity)` 修改为 `max(group, key=lambda n: n.pitch)`。
- **原因**：通过音高排序锁定高声部（Soprano）主旋律，规避转录模型的力度预测噪声。
- **影响**：主旋律识别的正确率与平滑度大幅提高，自动生成的简谱更动听。

# 36 键缩编谱五线谱对照审查设计

> 作者：JucieOvo  
> 日期：2026-07-01  
> 阶段：设计  
> 状态：已按对话确认整理，待用户审阅  

## 一、背景与目标

本项目用于将现实世界钢琴曲转换为可在游戏 36 键琴盘上演奏的 YAML 曲谱。当前 `svsep_mpdr_v3` 缩编精排结果存在综合问题，用户反馈无法区分具体属于声部、节奏、音区还是符号化输出问题，因此需要建立一个面向乐理盲用户也可理解的五线谱对照审查流程。

本设计的目标不是直接修复算法，而是先把当前三个目标 YAML 转换为可读谱面视图，并以原曲音频转录结果作为参考，按照现实钢琴谱排版和缩编规则审查当前 36 键版本的问题。

本次审查对象限定为：

1. `F:\NTEZMusic\config\one_last_kiss_svsep_mpdr_v3.yaml`
2. `F:\NTEZMusic\config\tada_koe_hitotsu_svsep_mpdr_v3.yaml`
3. `F:\NTEZMusic\config\cruel_angel_svsep_mpdr_v3.yaml`

## 二、总体方案

采用“双源交叉验证审查”方案：

1. 第一参考源：项目现有 MIDI，代表当前项目已有音频转录结果。
2. 第二参考源：重新从原曲音频转录得到的新 MIDI，作为独立参考。
3. 被审查对象：当前 `svsep_mpdr_v3.yaml` 反解后的 36 键 MIDI / MusicXML。

三路谱面数据互相对照：

- 现有 MIDI vs 当前 YAML：检查当前精排相对生成源损失了什么。
- 新转录 MIDI vs 当前 YAML：检查独立参考下仍成立的问题。
- 现有 MIDI vs 新转录 MIDI：识别参考转录自身不稳定区域。

审查结论分为四类：

| 结论类型 | 含义 |
|---|---|
| 高置信精排问题 | 可以直接进入后续算法修正设计 |
| 中置信疑似问题 | 需要结合音频试听或谱面局部复核 |
| 参考转录不稳定 | 暂不归因给 YAML 精排 |
| 可接受缩编取舍 | 虽然与原曲不同，但符合 36 键限制下的合理简化 |

## 三、输入与谱面模型

每首曲子形成三路谱面数据：

| 路径 | 名称 | 作用 |
|---|---|---|
| A 路 | existing-reference | 项目现有 MIDI，代表已有音频转录参考 |
| B 路 | fresh-reference | 重新从原曲音频转录生成的新 MIDI，作为独立参考 |
| C 路 | reduced-target | 当前 `svsep_mpdr_v3.yaml` 反解得到的 36 键 MIDI / MusicXML |

三路数据统一转换为内部谱面事件模型，至少包含：

- 起始拍点；
- 持续拍数；
- MIDI pitch；
- velocity；
- 原始声部或估计声部；
- 小节号；
- 拍内位置；
- 是否属于旋律候选；
- 是否属于低音锚点；
- 是否属于中间和声填充；
- 是否落入 36 键目标音域；
- 对应 YAML 事件编号，便于回溯定位。

## 四、YAML 反解流程

当前 YAML 是游戏演奏格式，不是标准谱面格式，因此需要先反解为谱面视图。

反解步骤：

1. 读取 `song.bpm`、`beat_unit` 和 `score`。
2. 将 `-1`、`1`、`+1` 等 token 映射回 MIDI pitch。
3. 将和弦 `[a b c]` 映射为同起点多个音符。
4. 将 `beat` 累积为绝对拍点。
5. 保留原 YAML 事件编号，方便报告定位。
6. 输出反解 MIDI、MusicXML 与 JSON 对照数据。

反解结果只表示“36 键缩编结果的谱面视图”，不声称它等同官方钢琴谱。

## 六、小节与时间对齐

对比不按“第 N 个事件”硬比，而按拍点和小节窗口比。

对齐规则：

1. 使用 YAML 的 BPM 与参考 MIDI 的 tempo 建立拍点轴。
2. 将全曲切为固定窗口：
   - 主窗口：1 小节；
   - 细窗口：0.5 拍或 1 拍；
   - 局部问题窗口：按异常触发自动扩大到前后 1 小节。
3. 对每个窗口统计：
   - 参考旋律范围；
   - 目标旋律范围；
   - 低音锚点是否存在；
   - 和弦密度；
   - 左右手/上下声部分布；
   - 音区碰撞；
   - 节奏事件数量；
   - 36 键压缩后的音程轮廓保真度。

允许的对齐误差：

- 起音偏差在一个量化单位内，视为可对齐；
- 极短装饰音允许落在同一局部窗口内比较；
- 不要求逐音完全相同；
- 重点比较结构功能，例如旋律走势、低音支撑、密度分布、声部清晰度。

禁止的处理：

- 不自动补不存在的旋律；
- 不自动假设参考谱有错；
- 不把无法解释的差异静默忽略；
- 所有被忽略或降置信度的问题必须写入报告。

## 七、审查规则

### 7.1 硬性问题

以下问题直接判为需要修正：

1. 超出 36 键映射范围：YAML token 无法映射回合法音高，或反解 pitch 超出目标范围。
2. 同一时间片同键重复：同一事件重复 token，或不同表达最终落到同一游戏按键。
3. 同拍密度超过配置上限：单事件音符数超过 `max_chord_notes`，或超过游戏稳定同按能力。
4. 节拍总长不一致：YAML 总拍数与参考谱主干长度明显不一致。
5. 非法或不可解析事件：事件缺字段、`notes` 无法解析、`beat` 非正数。

### 7.2 主旋律可见性

检查缩编谱是否保留参考谱中的重要上声部走势：

- 参考谱中连续高音旋律，在 YAML 中不应被中低声部盖住；
- 旋律候选不应频繁跳到低音区；
- 旋律线不应被过度合并成块状和弦；
- 强拍上的旋律音优先级应高于伴奏填充音；
- 若必须删音，优先删重复八度、低信息量填充音，而不是旋律骨干。

### 7.3 低音锚点与和声支撑

检查缩编谱是否保留钢琴谱常见低音功能：

- 每个和声重心窗口应尽量保留低音根基；
- 低音不应频繁折叠到旋律附近；
- 左手低音不应与右手旋律挤在同一狭窄音区；
- 长低音或分解低音可以缩短，但不能完全失去低音方向；
- 如果参考谱有明显低音进行，目标谱不能只剩中高音和弦。

### 7.4 声部分层与左右手逻辑

输出谱应尽量像一个可阅读的双手钢琴缩编：

- 高声部通常承载旋律；
- 低声部通常承载低音/伴奏；
- 中声部作为和声填充，不应主导全曲；
- 左右手交叉应少量出现，不能成为常态；
- 同一小节内音区角色应相对稳定，不应每拍都上下乱跳；
- 内声部不应挤压旋律和低音。

### 7.5 和弦密度与可演奏性

YAML 是游戏键盘输入格式，和弦密度要同时考虑乐理和游戏输入：

- 同拍音符过多会导致听感糊成一团；
- 半音组合与多音同按叠加会增加输入不稳定；
- 36 键缩编不宜保留过多八度重复；
- 快速连续和弦不应每个都满密度；
- 强拍可稍密，弱拍应更轻。

### 7.6 节奏骨架与织体形态

缩编需要保留关键织体：

- 分解和弦不能全部压成大块和弦；
- 快速旋律不能被错误合并；
- 伴奏型应保留节奏轮廓；
- 长音可以转成重复击键，但必须有音乐功能；
- 休止和断句要保留，否则谱面会没有呼吸。

### 7.7 可接受缩编取舍

以下差异不直接判错：

1. 八度压缩：只要旋律/低音角色仍清楚即可接受。
2. 省略内声部：中间填充音、重复八度、低信息量五度可删。
3. 简化复杂和弦：保留根音、三音、七音或主要色彩音即可。
4. 局部节奏近似：极短装饰音可合并或省略，但主旋律节奏和强拍骨架要保留。
5. 声部重排：可以改变原始左右手分配，但不能破坏听感层次。

## 八、问题分级

| 等级 | 含义 | 后续动作 |
|---|---|---|
| Critical | 明显错误，影响演奏或结构对齐 | 必须修正 |
| Major | 明显影响听感或钢琴谱逻辑 | 优先修正 |
| Minor | 局部不自然，但可接受 | 记录，视情况修正 |
| Info | 参考转录不稳定或仅供观察 | 不直接修正 |

## 十、报告结构

每首曲子的 `summary.md` 包含：

1. 输入材料：当前 YAML、现有 MIDI、新转录 MIDI、原曲音频。
2. 全曲统计：总拍数、总事件数、最大同拍音数、平均同拍音数、旋律候选保留率、低音锚点保留率、高密度事件比例、半音 token 比例、参考源一致性评分。
3. 问题摘要表。
4. 分类型分析：主旋律可见性、低音锚点、声部分层、和弦密度、节奏织体、输入稳定性。
5. 高置信问题详述：定位、参考谱现象、当前 YAML 现象、违反规则、可能根因、后续算法建议。
6. 需听感复核片段：不直接判错原因、建议试听范围、需要关注的听感点。

总报告 `docs/score_audit_svsep_mpdr_v3.md` 汇总三首曲子的共性问题，重点回答：

- 当前 `svsep_mpdr_v3` 的主要精排缺陷是什么；
- 哪些问题是曲目特定，哪些是算法共性；
- 后续应该改 MPDR 评分、声部分离、音区规划、节奏压缩，还是 YAML 输出规则；
- 哪些问题可以用规则修，哪些必须引入更强的谱面结构建模。

## 十一、执行边界

本阶段只做审查与设计，不直接修算法：

1. 不直接修改 `src/audio_to_yaml_converter.py`。
2. 不覆盖任何已有 YAML、MIDI、音频文件。
3. 不把自动审查结果当作绝对真理；报告必须区分高置信与需复核。
4. 不使用 Mock、Stub 或伪造转录结果。
5. 不用不存在的官方谱补充结论。
6. 不做规避游戏检测、后台注入或绕过行为。
7. 不把 36 键版本强行要求等同完整 88 键钢琴谱。

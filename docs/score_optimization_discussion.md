# adaptive_octave_fold 优化 -- 双层注意力推理

> 日期：2026-04-27  
> 状态：推理中

---

## 一、问题建模

当前 `adaptive_octave_fold` 是一个**单层因果全局注意力**系统：

```
ref_pitch(t) = (1-α) * ref_pitch(t-1) + α * avg_mapped(t)
```

所有时间片通过一根平滑线串联。前段的高音区 `ref_pitch` 会"拖滞"后段低音区，需要多个时间片才能校正。这等价于 Transformer 中全局线性注意力的"无关 token 强制耦合"问题。

**约束**：游戏不支持延音和力度，键盘 36 键 C3-B5 固定。

**目标**：引入"叠加注意力"——全局层决定整体框架，局部分段层决定左右手拆分和和弦简化。

---

## 二、候选方案对比

### 方案 A：趋势约束（改折叠层）

在 `_adaptive_octave_fold_slice` 的 k 选择中，代价函数由全局趋势和局部 ref_pitch 加权叠加：

```
cost(k) = w_g * abs(avg(pi+12k) - global_ref[i]) + w_l * abs(avg(pi+12k) - local_ref)
```

**优势**：改动最小，只改一个函数  
**劣势**：
- 全局趋势线提取和 k 选择耦合在一起，调参空间高（2 个权重 + alpha）
- 局部分段需要实时维护 local_ref，段边界重置逻辑嵌入在逐片循环中
- 单函数承担多重职责，出错时排障困难

### 方案 B：多尺度 k

同时维护 global_k 和 local_k，local_k 只能在 global_k ±1 八度内选择。

**优势**：实现简单  
**劣势**：
- 八度粒度太粗（只有 -1/0/+1 三个选项）
- 无法处理左右手拆分和和弦简化（B 方案只改了折叠，没涉及简化）

### 方案 C：两阶段解耦

阶段 1：全局趋势折叠（与原算法类似但 alpha 更慢）  
阶段 2：每段内独立做左右手拆分 + 简化

**优势**：
- 职责分离，两阶段互不污染
- 折叠算法改动小，简化作为独立后处理
- 段边界处理清晰

**劣势**：
- 折叠后的音高已失真，基于失真音高判定左右手可能不准
- 阶段 2 需要重新映射（简化后再折叠），增加处理步骤

---

### 方案 D（最优）：全局趋势参照 + 前置段内简化

结合 C 的优点并修复其缺陷：**在折叠之前做左右手判定和简化**。

```
所有判断基于原始 MIDI 音高（88 键完整信息），不依赖折叠后的失真数据。
```

**核心流程**：

```
阶段 0：量化分组（不变）
  grouped_pitches: {time_index → [pitch, ...]}

阶段 1：全局趋势线提取
  1a. 粗粒度窗口采样：按 4 拍窗口对全局音域重心做中值
  1b. 全曲双向平滑（非因果）：对整个重心序列做指数平滑 → global_ref[t]
  用途：在阶段 3 折叠时替代原有 ref_pitch，保证跨段听感框架一致

阶段 2：休止符分割 + 段内自适应简化
  2a. 分割：检测时间片网格中连续 N 个空时间片 → 段边界
  2b. 段内左右手判定：
      - 基于原始 MIDI 音高分布，自适应计算分割线 split_pitch
      - 方法：段内音高密度双峰检测 → 若存在双峰，取谷底
              若无明显双峰 → 使用段内中位数
  2c. 段内简化：
      - 右手音（≥ split_pitch）：全部保留，不裁剪
      - 左手音（< split_pitch）：激进裁剪
        - 若 ≤ 2 个左手音：全部保留（可能是单音或双音伴奏）
        - 若 3-4 个左手音：保留最低音 + 与最低音形成纯五度/纯四度的音
        - 若 ≥ 5 个左手音：仅保留最低音（根音）
      - 输出：简化后的 grouped_pitches_simplified

阶段 3：自适应八度折叠（使用 global_ref 替代 ref_pitch）
  对简化后的 grouped_pitches_simplified 执行逐时间片八度折叠
  折叠时使用 global_ref[t] 作为参考中心（替代原始 ref_pitch 在线计算）

阶段 4：碰撞消解 + Token 输出（不变）
```

## 三、关键设计决策

### 3.1 全局趋势线提取

**为什么不用现有 ref_pitch（alpha=0.2）？**
现有的因果平滑太"快"，对局部变化敏感。全局趋势需要更慢、更稳。

**方案**：
```
1. 将全曲按滑动窗口（window=4拍, step=1拍）分组
2. 每个窗口内的音符取中位数（抗异常值）
3. 对整个窗口序列做双向指数平滑 → 非因果的稳定趋势线
4. 插值回每个时间片粒度
```

**为什么要非因果（双向）？**
全局趋势不需要实时计算，batch 处理可以看到完整曲谱。双向平滑消除了因果平滑的相位滞后，趋势线更准确地刻画"曲子本来的音域重心"。

### 3.2 休止符分割粒度

**分割条件**：连续 ≥2 个空时间片（即 ≥0.5 拍，以 quantize_beat=0.25 计）

**原因**：
- 1 个空时间片（0.25 拍）太细碎，可能是八分休止或和弦之间的短断，不是乐句边界
- 3 个及以上（≥0.75 拍）太宽松，可能漏掉明显的句读
- 2 个（0.5 拍 = 半拍休止）是实用的折中，对应八分休止符长度

### 3.3 左右手自适应分割线

**双峰检测**：
```
1. 构建段内音高直方图（bins = MIDI 21~108, 88键）
2. 高斯平滑直方图（sigma=3 半音）
3. 寻找峰值：scipy.signal.find_peaks（或手动实现）
4. 若存在 ≥2 个峰：
    取最低峰和最高峰之间的谷底作为分割线
5. 若不足 2 个峰（单音区或无伴奏纯旋律段）：
    使用段内音高中位数作为分割线
6. 兜底：MIDI 60 (C4) 作为绝对兜底
```

### 3.4 左手和弦简化策略

三个档位，基于左手区域音符数量 `count`：

| count | 策略 | 原因 |
|-------|------|------|
| ≤2 | 全部保留 | 单音或双音伴奏不会造成听感臃肿 |
| 3-4 | 保留最低音 + 上方纯五度/纯四度（若存在） | 保留和声骨架，去掉三音/七音等色彩音 |
| ≥5 | 仅保留最低音 | 密集和弦只留根音，保证低音功能 |

### 3.5 右手完整保留

右手区域不做任何 `max_chord_notes` 裁剪。原因：
- 右手通常承载旋律 + 旋律装饰音 + 上方和弦填充
- 这些音符共同构成"主歌听感"，裁剪会直接伤害辨识度
- 左手已经做了激进简化，给右手留出密度空间

## 四、与当前实现的对比

| 维度 | 当前 v2 | 方案 D |
|------|---------|--------|
| ref_pitch | 因果在线计算 (α=0.2) | 全曲双向平滑趋势线 `global_ref` |
| 分段依据 | 无分段 | 休止符分割 |
| 左右手判定 | 无 | 段内双峰检测，自适应分割线 |
| 和弦裁剪策略 | 全局一刀切 (max_chord_notes=4) | 右手不限 / 左手分档简化 |
| 段边界处理 | 无此需求 | 段间全局趋势线自然过渡 |
| 原算法改动 | -- | 折叠层改参考线；新增分段+简化层 |

## 五、需要新增的配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `left_hand_simplify` | true | 是否启用左手简化 |
| `phrase_gap_threshold_beats` | 0.5 | 休止符分割阈值（拍数） |
| `global_trend_window_beats` | 4.0 | 全局趋势采样窗口（拍数） |
| `global_trend_alpha` | 0.05 | 全局趋势线平滑系数 |
| `segment_split_mode` | "bimodal" | 双峰检测 / "median" 中位数 / "fixed_60" 固定 C4 |

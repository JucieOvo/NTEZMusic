# 面向游戏三八度键盘的 MIDI 自适应缩编算法 —— 实现纪实

> 作者：JucieOvo  
> 日期：2026-04-27

---

## 一、项目起源

**背景**：《异环》是一款内置钢琴演奏系统的游戏。游戏键盘布局为三行——QWERTY 行、ASDFGHJ 行、ZXCVBN 行——共 36 键，恰好覆盖 3 个完整八度（C3-B5）。

**目标**：将完整钢琴 MIDI（88 键，约 7¼ 八度）自动缩编到游戏 36 键可执行范围，且**尽量保持原曲听感、主旋律辨识度和和声功能**。

**输入**：Animenz 改编的《残酷天使的行动纲领》钢琴版 MIDI，原始 3423 个音符，音域跨度 79 半音（约 6.6 八度）。

**输出**：YAML 简谱文件，可直接由自动弹奏器送入游戏。

## 二、三版算法的演进

### 2.1 第一版：三分区强制映射（v1，已废弃）

**核心假设**：游戏的三行键盘对应三个"功能区"——
- 高行（QWERTY）：旋律区，C5-B5
- 中行（ASDFGHJ）：和声区，C4-B4
- 低行（ZXCVBN）：低音区，C3-B3

**算法架构**（约 600 行）：
```
乐句分割 → 三层声部分离 → 独立 DP 映射 → 碰撞消解
```

- 旋律用动态规划（DP）映射到高音区 [72, 83]
- 低音用 DP 映射到低音区 [48, 59]
- 和声用匈牙利算法追踪内声部线，映射到中音区 [60, 71]
- DP 代价函数：锚定代价 + 八度跳变惩罚 + 偏移代价 + 轮廓代价

**问题一：旋律被锁死在 +1 (C5)**。原曲中所有 C 音（pitch class 0）——不论原曲是 C4、C5、C6 还是 C7——全部被映射到 C5 = `+1`。`+1` 恰是高音区的底边界，紧邻中音区顶部 B4 (`7`)，旋律仅高出 1 个半音。实际听感：旋律"淹没"在伴奏中，高潮句"奇迹"听起来像最低音。

**问题二：global_linear 模式的 round() 误杀**。此前实现过一种"全局线性压缩"模式，将全曲音域按统一比例线性压缩到 C3-B5。`round()` 四舍五入会把相邻半音错误地合并——例如 C5(72) 压缩后 `round` 到 B4(71)，导致 `+7` 变成 `+1`。这是用户最早指出的"7 变成 1"的根因。

### 2.2 关键认知转折

用户的一句反馈彻底改变了设计方向：

> "原先分为三个区是因为游戏为了方便玩家操作，在视觉上分为了三个区，被原来那个傻子解读错了。"

**真相**：游戏的三行键盘仅仅是**视觉操作分区**，为玩家手指操作提供便利。36 键形成的是**一个完整的连续 3 八度音域**。`+` / 无 / `-` 前缀只是键位记号，不是功能角色分配。

- QWERTY 行 ≠ 旋律区
- ASDFGHJ 行 ≠ 和声区
- ZXCVBN 行 ≠ 低音区

**所有 36 键平等可用。旋律可以出现在任何位置。**

### 2.3 第二版：自适应八度折叠（v2，当前版本）

**核心思想**：用**自适应八度折叠**把全曲塞进 36 键窗口，不做功能分区。维护一个平滑参考中心 `ref_pitch`，逐时间片寻找能将全部音符折叠进窗口的统一八度偏移 `k`。

**算法流程**（约 180 行）：

```
Phase 0: 量化分组 → 按 0.25 拍将 MIDI 音符分配到时间片网格

Phase 1: 自适应八度折叠（逐时间片）
  ├── 维护平滑参考中心 ref_pitch（初始值 65.5 = F4，窗口中心）
  ├── 对每个时间片的音符集：
  │   ├── 寻找能使全部音符落入 [48, 83] 的统一八度偏移 k
  │   ├── 和弦自身跨度 ≤ 36 半音时，存在共同 k → 选最接近 ref_pitch 的
  │   └── 跨度 > 36 半音时（极少见），各自独立映射
  ├── 指数平滑更新 ref_pitch：
  │   ref_pitch = 0.8 * ref_pitch + 0.2 * avg_mapped
  └── 转换为 YAML token，去重 + 密度裁剪

Phase 2: 碰撞消解
  ├── 同键位去重
  └── 超 max_chord_notes(4) 时优先保留最高音 + 最低音

Phase 3: Token 输出
```

**关键设计决策**：

1. **和弦统一 k**：同一时间片的所有音符使用相同的八度偏移量 `k`，保证了和弦内部音程关系的**绝对精确保留**。大三和弦经过八度折叠后仍然是大三和弦。

2. **ref_pitch 指数平滑**：参考中心不会突变。当音乐音区整体上移或下移时，`ref_pitch` 平滑跟随，八度切换自然隐晦，发生在乐句的呼吸间隙。

3. **不区分角色**：旋律、低音、和声不再被强制分配到不同行。它们共同占据 36 键窗口，保持原始的音高相对关系。

### 2.4 v1 vs v2 对比

| 维度 | v1（三分区） | v2（自适应折叠） |
|------|-------------|-----------------|
| 代码量 | ~600 行 | ~180 行 |
| 参数数量 | 15 个 | 1 个（ref_smoothing） |
| 音区策略 | 旋律锁 [72,83]、和声锁 [60,71]、低音锁 [48,59] | 全 36 键动态使用 |
| 旋律自由度 | 限定高行 12 键 | 可在 36 键任何位置 |

| 八度迁移率 | 63% | 50% |

## 三、修饰键冲突问题与解决

### 3.1 游戏修饰键机制

游戏钢琴的 7 个白键（1-7）可通过修饰键改变音高：
- **Ctrl**：升半音，影响键位 1(→#1)、4(→#4)、5(→#5)
- **Shift**：降半音，影响键位 3(→b3)、7(→b7)
- **关键发现**：修饰键是**全局状态**，同一时刻只有一个生效。后按入的会顶掉先前的，"像一个只能容纳一个状态的栈"。

### 3.2 冲突场景

当同一和弦同时包含升半音（如 `#1`、`#4`、`#5`）和降半音（`b3`、`b7`）时，Ctrl 和 Shift 无法同时生效。

### 3.3 解决方案：1ms 交替切换

在 `piano_auto_player.py` 中实现：

1. 检测和弦是否同时包含 Ctrl 和 Shift 修饰键
2. 拆分两组基础键：
   - **Ctrl 组**：升半音键 + 不受 Ctrl 影响的自然键（键位 2、3、6、7）
   - **Shift 组**：降半音键 + 不受 Shift 影响的自然键（键位 1、2、4、5、6）
   - 不受两种修饰影响的自然键（键位 2、6）全程按住
3. 1ms 内完成 Ctrl → Shift 切换：

```
t=0:     按下 Ctrl → 按下 Ctrl 组键
t=1ms:   释放 Ctrl 组键 → 释放 Ctrl → 按下 Shift → 按下 Shift 组键
t=hold:  释放全部
```

### 3.4 延迟叠加问题的发现与修复

**问题**：最初的修饰键切换间隔设为 50ms，加上 YAML 中的 `key_press_seconds`（50ms），总延迟叠加到 100ms，远超人耳听觉融合阈值（~50ms），导致和弦听起来像两个分离的琶音。

**修复**：
- 修饰键 stagger 降至 1ms
- YAML 中 `key_press_seconds` 移除（设为 0）
- 播放层保底 1ms 最小按键时间（防止游戏吞音）
- 所有延迟只在播放器内部处理，YAML 保持纯净

### 3.5 YAML 与播放器职责分离

最终的清晰分工：

| 层 | 职责 | 延迟 |
|----|------|------|
| YAML 生成器 | 音高映射、八度折叠、和弦密度控制 | 无 |
| 钢琴播放器 | 按键时序、修饰键切换、吞音保底 | 1ms stagger + 1ms 保底 |

## 四、bug 追踪与修复记录

### 4.1 跨乐句音高污染（v1 发现）

**现象**：`grouped_pitches` 是全局字典，乐句 A 扫描自己的时间跨度时，若乐句 B 的音符恰好在 A 的延音区间内开始，会被错误包含。

**修复**：在声部分离阶段引入 `phrase_pitch_set`——以 `(time_idx, pitch)` 二元组精确过滤本乐句的音符。

### 4.2 中值滤波凭空构造条目（v1 发现）

**现象**：中值滤波对 `raw_line` 中没有值的索引位置，因为窗口中有相邻值而错误地"构造"出新条目。导致一条声部线凭空多出数百个音符。

**修复**：中值滤波仅对 `raw_line` 中存在的索引执行，保持稀疏性。

### 4.3 单音符重复分配旋律+低音（v1 发现）

**现象**：时间片只有一个音符时，同时被分配给旋律和低音两条线，经 DP 独立映射后变成两个输出音符——一个在高音区、一个在低音区——重复发声。

**修复**：低音仅在时间片有至少 2 个不同音高时单独分配。

### 5.3 核心技术要点

1. **精确音程保留**：所有映射都是 ±12k 半音的八度移位，不破坏任何半音关系。和弦品质完全保留。

2. **统一八度偏移**：同一时间片的全部音符共享同一个 `k`，和弦内部音程绝对不变。

3. **平滑参考跟踪**：`ref_pitch` 指数平滑使八度切换隐匿于乐句自然呼吸处，无断续感。

4. **36 键动态使用**：旋律可以在低行发声、低音可以在高行出现——只要整体音程关系对。

5. **修饰键 1ms 交替**：低于人耳融合阈值，混合升降半音和弦听感等同于同时发声。

- **YAML 曲谱**：`config/cruel_angel_final.yaml`
- **转换报告**：`work/cruel_angel_final/conversion_report.json`
- **播放命令**：`python src/piano_auto_player.py --config config/cruel_angel_final.yaml`

## 六、局限性

1. **3 八度硬上限**：全曲音域被压缩到 36 半音内。原曲中极宽的音区跳动（如超过 3 个八度的旋律大跳）会被截断。

2. **C 音聚集效应**：所有 C 音（pitch class 0）只能映射到 C3、C4、C5 三者之一。若原曲大量使用 C 音不同八度的变化，在输出中会"折叠"到少数几个音高。

3. **修饰键 1ms 切换**：虽低于融合阈值，但在极其严苛的监听条件下可能被察觉。游戏本身的音频引擎延迟也可能影响效果。

4. **无调性检测**：算法不检测乐曲调性，不做调内调外区分。所有音高平等对待。

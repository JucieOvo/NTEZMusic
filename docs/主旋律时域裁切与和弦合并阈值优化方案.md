# 主旋律时域裁切与和弦合并阈值优化方案

## 1. 背景与问题诊断
在主旋律提取时，用户发现“主旋律有些地方不对，但一会又对了，可能是裁切和分组的问题”。
经过对 `src/midi_to_upagain_yaml.py` 中的 `MidiMelodyExtractor.extract_melody_events` 代码进行深入审计，我们发现了核心问题所在：

### 1.1 宽阈值导致连续快速单音被误合并
在“核心算法1”中，程序将相邻音符按 **80毫秒 (0.08s)** 的时间窗口合并为“同一个和弦组”：
```python
if abs(note.start - group[0].start) <= 0.08:
    group.append(note)
```
*   **物理尺度分析**：
    *   在速度 BPM = 120 的曲子里，一个 16 分音符的时值是 **125毫秒**。如果在较高速度下（如 BPM = 150），16 分音符仅为 **100毫秒**。
    *   录音转录或演奏习惯中，前后的连续单音（如颤音/Trill、快速半音阶、装饰音）的时间间距极易降至 80ms 左右或以下。
    *   如果相邻的连续主旋律音符（例如主旋律中的 Note A 和 Note B）的时值间距 $\le 80\text{ms}$，它们会被**错误地归为同一个“和弦发声组”**。
*   **后果**：由于每个和弦组经过平滑算法后**只会保留唯一的 1 个主音**，这导致 Note A 或 Note B 的其中一个会被永远丢弃。听感上就会表现为快速段落处“漏音”、“主旋律不对”，而在速度慢的段落（音符间距大）“一会又对了”，产生明显的跳切缺块。

---

## 2. 优化方案设计

### 2.1 缩减和弦分组的时间容差（Onset Grouping Window）
真正的和弦（同时弹下的音符）在物理击键上的起音时间差通常非常小，一般在 10 ~ 20 毫秒之间，极少超过 30 毫秒。
我们将 onset 容差从原先的 **80毫秒 (0.08s)** 缩减至 **30毫秒 (0.03s)**。

*   **隔离合并效果**：
    *   当 $\Delta t \le 30\text{ms}$ 时：视为钢琴和弦，两个音符在空间上重叠发声，通过动态规划选取其中 1 个（最高音/最强音路径），避免在 YAML 中生成非法的并发重音。
    *   当 $\Delta t > 30\text{ms}$ 时：视为玩家弹奏的连续单音流（即使是非常快速的 16 分音符或装饰音），它们被划分为独立的组，使得每一个音符都得以完整保留，随后通过后面的“时域物理单音化剪裁”自然衔接。

### 2.2 优化后的参数细节
在 `src/midi_to_upagain_yaml.py` 的 `extract_melody_events` 中更改：
```python
        # 核心算法1：将 onset 时间容差由 0.08 缩短为 0.03，防止快速连弹被误当作和弦合并丢弃
        onset_groups = []
        for note in melody_notes:
            placed = False
            for group in onset_groups:
                if abs(note.start - group[0].start) <= 0.03:  # 变更点
                    group.append(note)
                    placed = True
                    break
```

## 3. 执行方案与变更细节（形式 A）
- **操作类型**：代码修改
- **目标组件**：`src/midi_to_upagain_yaml.py` 中的 `MidiMelodyExtractor` 组件
- **修改内容**：将 `extract_melody_events` 内分组判断的时间阈值由 `0.08` 修改为 `0.03`（第126行）。
- **原因**：防止快速音级行进（BPM高或有装饰音时）被误判为同点和弦而合并裁剪掉。
- **影响**：快速音阶及琶音的颗粒度与音符完整率大幅提升，彻底消除“忽对忽错”的跳变现象。

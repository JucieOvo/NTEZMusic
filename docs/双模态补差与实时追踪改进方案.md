# 音视频双模态补差与实时追踪改进方案

## 1. 目标与意图
在原有的视觉分离方案基础上进行深度升级，全面引入**双重补差机制**与**实时追踪架构**。通过将音频特征（精准强弱、音符级解析）与视觉特征（物理位置、左右手识别）结合，双向校验音高，并利用提取出的各个音符“音量大小”区分主调与伴奏，实现高准确度、实时流式输出的智能琴谱分析系统。

## 2. 核心架构与逻辑
本架构严格遵守不采用降级策略的准则，任何维度的特征提取失败将直接告警中断，以保证最终琴谱数据的真实与高可靠。

1. **属性解耦与双轨提取**：
   - **音频分析轨**：流式解析音频，提取绝对音高（Pitch）与力度/强弱（Velocity/Volume）。
   - **视觉分析轨**：流式解析视频，提取基于键盘映射的物理音高（Pitch）与左右手归属标签（L/R）。

2. **音高双重校验与判定补差**：
   - 建立高精度的音画同步时间轴映射。
   - 当视觉推断的音高与音频解析的音高在极窄时间窗口（如 50ms）内重合时，视为有效触键。
   - 补差原则：利用音频克服视觉的手指遮挡问题，利用视觉克服音频的和弦声学混叠问题。双侧结果必须通过严格校验，若遇硬性不匹配（且非合理泛音），抛出提取异常。

3. **基于手部音量的主旋律判定**：
   - 钢琴演奏中主旋律通常伴随更高的触键力度（Velocity）。
   - 系统将音频提取到的“音量/力度”标签通过时间戳与音高关联到具体的左/右手触键事件上。
   - 实时计算各声部/各手的瞬态能量，将当前时刻平均力度显著较大的一侧或特定音轨，自动打上“主旋律（Main Melody）”的结构化标签。

4. **实时追踪与流式处理流水线**：
   - 抛弃离线全局扫描，采用基于时间滑动窗口（Sliding Window）的实时跟进结构。
   - 视频帧与音频块进入先进先出（FIFO）队列，实时处理、实施比对、实时输出音符事件流。

## 3. 模块划分设计
- **流式接驳处理模块**：维护音频缓冲块与视频帧流，统一音画时间戳映射，向后方输入严格对齐的实时数据片。
- **音频特征实时解析模块**：执行流式Onset检测，提取并输出结构化音频数据块 `{timestamp, pitch, velocity}`。
- **视觉姿态与琴键空间检测模块**：追踪实时手部关键点位置与琴键区域坐标碰撞，输出视觉数据块 `{timestamp, visual_pitch, hand_side}`。
- **强校验与补差决策引擎**：核心业务模块。
  - 第一步：对齐双模态时间窗。
  - 第二步：执行 Pitch 交叉验证。
  - 第三步：结合 Velocity 完成手部音量的量化。
  - 第四步：计算并推断主旋律声部归属。输出融合事件 `{timestamp, pitch, velocity, hand=L/R, is_melody=True/False}`。
- **流式琴谱生成模块**：将融合事件序列实时序列化为 MusicXML 或 MIDI 指令流输出。

## 4. 数据流
1. `Audio/Video Stream` -> `流式接驳处理模块` -> （分割双路流）。
2. 路段A：提取 `Pitch(Audio)` + `Velocity`。
3. 路段B：提取 `Pitch(Visual)` + `Hand_Label`。
4. `决策引擎` 并发接收 A 和 B -> 时间戳咬合合并。
5. 通过 `Velocity` 比较判决主旋律 -> 构建最终的 `NoteEvent` 对象实体。
6. `NoteEvent` 序列 -> `流式琴谱生成模块`。

## 5. 风险点与防范
1. **多音并发的力度分配难题（和弦困境）**：同一时刻按下多个键，音频整体解析出的泛力度很难直接分拆给单根手指。需要结合前置的视觉下键加速度来辅助映射绝对 Velocity，或者严格限制音频提取引擎必须具备复音（Polyphonic）Velocity 分离能力（由于严禁Mock数据的伪造分配，若底层算法无法剥离单音力度，应报错拦截，拒绝生成均分假数据）。
2. **实时计算资源过载**：视觉逐帧评估极吃性能。系统必须采用合理的关键帧间隔和严格的队列调度机制，确保不会发生内存溢出，若处理延迟过载则显式抛出 Timeout 错误，不采取抽帧降级。

## 6. 执行顺序规划
1. 搭建双路流式实时接口框架，定义底层 `NoteEvent` 核心数据结构。
2. 集成并验证基于真实录音的流式音频特征解析算法（必须确保能精确输出复音的音高及独立音量）。
3. 开发和验证视觉流式手势捕获及空间碰撞提取。
4. 撰写并严格测试决策树逻辑：包含补差判定、力度计算与主旋律标定。
5. 最终串联为全链路追踪模型。

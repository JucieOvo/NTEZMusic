# UpAgain 曲谱仿 NTE 智能降维与自优化方案

## 1. 目标
解决直接粗暴剔除不支持音符（如黑键、越界高低音）导致的“曲谱旋律断层、听感极差”问题。我们将模仿项目 `src/audio_to_yaml_converter.py` 中的 `octave_fold` (八度折叠) 与 `svsep_mpdr` 旋律线提取思路，开发带有一套**“真·旋律提取 + 音等价折叠 + 自然音阶吸附”**的离线转换脚本。

## 2. 意图
刚才的初代转换器听感差，在于它犯了两个致命错误：
1. **错把伴奏当旋律**：原曲高音域旋律由于超限被脚本删除后，它选取了残存的低音伴奏作为最高音弹奏。
2. **黑键丢失导致节奏断裂**：EVA 主题曲存在大量的降号 (`b3` 即 Eb)，直接过滤导致主旋律出现大量休止符。
我们不能直接过滤，而需要先将所有曲谱文本转义为**绝对物理音高 (MIDI Pitch)**，锁定真实的最高旋律线后，再进行智能的**系统降维算法映射**，强行保留旋律的起伏和节拍。

## 3. 技术要点 (NTE 优化算法降维版)
- **绝对音高反算**：写一套解析算法，把 `-1` 算成 MIDI 的 48 (C3)，把 `+b3` 算成 75 (Eb5)。
- **True Melody (真旋律提取)**：在一个和弦里，先比对所有音的真实音高，选出真正的那个主旋律。
- **Octave Fold (八度折叠压缩)**：如果提取出的旋律大于 `84 (C6)` 或小于 `60 (C4)`，我们将对其加减 `12` 的倍数，将其无损平移压进 UpAgain 的 `60~84` 物理音域内。
- **Diatonic Snap (自然音阶吸附)**：UpAgain 只有 15 个白键。对于落在黑键上的音（如 `Eb`，即余数为 3），我们利用就近自然音阶算法，借位吸附为相邻的白键（如吸附为 `E`），确保没有任何一个旋律音被丢弃！

## 4. 模块划分与数据流
- 在 `upagain_yaml_converter.py` 中重构核心类为 `UpAgainSmartScoreConverter`。
- `parse_nte_token_to_pitch` 模块：完成文本 token 向 MIDI 音高的逆向映射。
- `pitch_to_upagain_token` 模块：包裹八度折叠与白键吸附逻辑，映射回安全域 token（如 `+1`）。
- **完全替换** `_process_notes` 逻辑，在生成新 `upagain_cruel_angel_thesis.yaml` 时直接输出最优化的单音序列串。

## 5. 风险点
由于黑键吸附白键实际上是将原曲的调式（如 C 小调）给粗暴拉正为了 C 大调，会产生一定的变调色彩误差，但这在 15 键物理限制且不丢节奏的要求下是理论上的最优质解。
